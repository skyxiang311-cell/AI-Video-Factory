# AI Video Factory 第一阶段设计规范

- 文档状态：已确认
- 日期：2026-08-11
- 阶段：项目初始化与设计规范
- 目标平台：中国抖音、小红书
- 首发模板：Knowledge 知识型模板

## 1. 背景与目标

AI Video Factory 用于把 PDF、文章、截图和文字资料转化为适合中国抖音、小红书传播的知识型竖屏短视频。系统必须先理解资料，再提炼重点并进行原创重构，最终形成有强钩子、高信息密度和收藏价值的中文视频，而不是逐句翻译、简单改写或复刻原始版式。

第一阶段只建立仓库骨架、协作约束、数据边界和工作流设计，不接入真实 AI、配音、素材或发布 API，也不实现完整功能。

## 2. 产品范围

### 2.1 本阶段范围

- 建立输入、研究、脚本、分镜、素材、配音、字幕和渲染模块的目录边界。
- 定义从输入资料到 1080×1920 MP4 的标准生产链。
- 规定 Storyboard JSON 是 AI 内容层与视频渲染层之间的稳定契约。
- 规定每个任务必须保存完整中间产物，以支持审阅、局部修改、失败重试和断点恢复。
- 只为 Knowledge 知识型模板确定第一版方向。

### 2.2 非目标

在核心视频生产链稳定之前，不开发：

- 登录、账号和权限系统；
- 付费、订阅和订单系统；
- SaaS 管理后台；
- 抖音、小红书等平台的自动发布；
- News、Ranking、Comparison 模板的完整实现；
- 与视频生产主链路无关的增长或运营功能。

## 3. 输出标准

- 画布：1080×1920 像素。
- 方向与比例：竖屏，9:16。
- 容器格式：MP4。
- 默认时长：60～180 秒。
- 默认语言：简体中文。
- 核心平台语境：抖音、小红书知识内容。
- 视觉要求：为竖屏重新设计层级、节奏和信息卡片，不机械复制原始杂志、PDF 或网页排版。

## 4. 总体工作流

```text
PDF / 文章 / 截图 / 文字
↓
内容提取
↓
AI 理解和重点提炼
↓
原创重构
↓
抖音 / 小红书口播脚本
↓
Storyboard JSON
↓
素材准备
↓
AI 中文配音
↓
动态中文字幕
↓
Remotion 动画与信息卡片
↓
FFmpeg 处理
↓
1080×1920 MP4
```

每个阶段只消费已经落盘的上游产物，并产生新的版本化产物。任何阶段失败时，可以从最近一次有效产物继续执行。

## 5. 内容生产规范

### 5.1 理解与提炼

输入层需要保留来源类型、来源标识、提取文本、页码或区块位置等可追溯信息。研究层负责识别主题、目标受众、核心事实、关键数字、因果关系、反直觉点和潜在风险。

事实、数字、时间、价格与专有名词必须能追溯到输入或经过确认的研究结果。国外内容涉及价格时必须明确货币单位，例如“日元”“人民币”，不能只输出数字。不确定或相互冲突的信息必须进入警告清单，不能静默猜测。

### 5.2 原创重构

脚本不能沿用原文段落顺序做逐句翻译，也不能只替换同义词。原创重构至少包括：

1. 根据中国用户的理解路径重新排序信息；
2. 选择一个清晰的中心结论；
3. 将资料压缩为 3～5 个递进知识点；
4. 使用自然中文口语解释概念与价值；
5. 增加开场钩子、段落转场和可收藏的总结；
6. 保留事实准确性，同时形成独立表达。

### 5.3 内容优先级

所有内容决策按以下顺序权衡：

1. 原创性与事实准确性；
2. 前三秒钩子；
3. 信息密度；
4. 收藏价值；
5. 中国用户的阅读和口语习惯；
6. 视觉表现与装饰。

## 6. 时长与叙事结构

默认视频长度为 60～180 秒。脚本和 Storyboard 应根据目标时长压缩或扩展知识点，但不能通过重复表达填充时长。

典型三分钟结构：

| 时间 | 叙事职责 | 输出要求 |
| --- | --- | --- |
| 0–3 秒 | 强钩子 | 用结果、反差、问题或利益点立即建立注意力 |
| 3–20 秒 | 为什么值得看 | 说明与用户的关系、观看收益或常见误区 |
| 20–140 秒 | 3～5 个核心知识点 | 每点有明确结论、解释、证据或例子，并形成递进 |
| 140–165 秒 | 总结压缩 | 把核心知识压缩成容易记忆的框架 |
| 165–180 秒 | 收藏结论 | 给出可复用、值得保存的结论或行动提示 |

## 7. 模块边界

| 目录 | 职责 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| `src/ingest/` | 读取 PDF、文章、截图、文字并统一提取 | 用户输入 | `source.json` |
| `src/research/` | 理解、核验、提炼重点和风险 | `source.json` | `analysis.json` |
| `src/script/` | 原创重构与中文口播脚本 | `analysis.json` | `script.json` |
| `src/storyboard/` | 将内容转为时间化场景契约 | `script.json` | `storyboard.json` |
| `src/assets/` | 准备图片、图标、数据卡片和音乐引用 | `storyboard.json` | `assets.json` 与本地素材 |
| `src/voice/` | 生成中文配音并记录时长 | `script.json` | `voice.mp3` |
| `src/subtitles/` | 生成时间化动态中文字幕 | 配音与脚本 | `subtitles.json` |
| `src/render/` | Remotion 渲染及 FFmpeg 辅助处理 | 分镜、素材、配音、字幕 | `final.mp4` |
| `src/shared/` | 共享类型、校验、任务和文件约定 | 各模块 | 稳定公共接口 |
| `apps/studio/` | 后续提供任务审阅、预览和局部重跑入口 | 任务产物 | 用户操作与预览 |

模块之间通过落盘 JSON 和显式媒体文件通信，不直接读取其他模块的临时内存状态或模型对话。

## 8. Storyboard JSON 契约

`storyboard.json` 是 AI 内容层和视频渲染层的唯一核心边界。内容层决定讲什么、何时讲、需要什么素材和强调什么；渲染层决定如何用 Remotion 把这些意图表现为动画、字幕和信息卡片。

第一版逻辑结构如下，具体 TypeScript Schema 在第二阶段实现：

```json
{
  "schemaVersion": "1.0",
  "jobId": "knowledge-20260811-001",
  "format": {
    "width": 1080,
    "height": 1920,
    "fps": 30,
    "durationMs": 180000
  },
  "template": "knowledge",
  "scenes": [
    {
      "id": "scene-001",
      "startMs": 0,
      "endMs": 3000,
      "purpose": "hook",
      "voiceText": "示例口播文本",
      "onScreenText": ["示例重点"],
      "visualIntent": "用结果反差建立注意力",
      "assetRefs": [],
      "emphasis": ["示例重点"],
      "transition": "cut"
    }
  ]
}
```

约束：

- 所有时间使用毫秒，场景时间不得重叠且必须落在总时长内。
- `voiceText` 是配音与字幕对齐的内容依据。
- `visualIntent` 描述视觉意图，不绑定某个具体 Remotion 组件。
- `assetRefs` 只引用 `assets.json` 中已声明的素材标识。
- 渲染层不得通过重新调用内容模型来补齐缺失信息；数据不完整时应明确失败并返回上游修正。
- 结构必须包含 `schemaVersion`，以支持后续兼容和迁移。

## 9. 素材、配音、字幕与渲染

### 9.1 素材准备

素材清单需要记录素材 ID、类型、用途、来源、授权或生成方式、本地路径和适配状态。素材画面应服务于原创叙事，不照搬资料原始版式。

### 9.2 AI 中文配音

配音以确认后的 `script.json` 为源，输出 `voice.mp3`。生成后记录实际时长，实际时长变化应触发字幕和分镜时间校准，而不是在渲染阶段静默拉伸音频。

### 9.3 动态中文字幕

`subtitles.json` 保存字幕文本、起止时间、分组和强调词。字幕需要适配手机竖屏阅读，控制单屏信息量，并避免与平台 UI 的高风险区域冲突。

### 9.4 Remotion 与 FFmpeg

Remotion 是主要视频视觉渲染引擎，负责场景动画、信息卡片、素材编排、动态字幕和主画面输出。FFmpeg 负责输入媒体标准化、音频处理、探测与校验、混流、转码和最终辅助处理。FFmpeg 不替代 Storyboard 驱动的主要视觉编排。

## 10. 任务目录与中间产物

每次生产任务必须拥有稳定且唯一的 `job-id`，所有中间产物存入：

```text
output/<job-id>/
├── source.json
├── analysis.json
├── script.json
├── storyboard.json
├── voice.mp3
├── subtitles.json
├── assets.json
└── final.mp4
```

产物职责：

| 文件 | 内容 | 可复用价值 |
| --- | --- | --- |
| `source.json` | 规范化来源、提取文本和来源定位 | 更换下游策略时无需重复解析输入 |
| `analysis.json` | 主题、受众、事实、重点、风险和内容角度 | 重写脚本时保留理解与研究结果 |
| `script.json` | 分段口播、钩子、知识点和总结 | 调整画面时无需重新生成内容 |
| `storyboard.json` | 场景时间、画面意图、字幕与素材需求 | 直接驱动视觉层局部修改和重渲染 |
| `voice.mp3` | 已确认脚本的中文配音 | 视觉重渲染时复用音频 |
| `subtitles.json` | 时间化字幕与强调信息 | 字幕样式调整时复用时间轴 |
| `assets.json` | 素材来源、路径和使用关系 | 重渲染时避免重复检索或生成素材 |
| `final.mp4` | 最终成片 | 交付与版本对比 |

产物必须先写入临时文件并通过结构校验，再以原子方式替换正式文件，避免任务中断留下半成品。生成文件只保存在本地或未来的任务存储中，不提交到 Git。

## 11. 局部重跑策略

系统根据发生变化的最早阶段重跑其下游：

- 只改动画、卡片或配色：复用全部 JSON、配音和素材，只重跑 Remotion/FFmpeg。
- 只改素材：更新 `assets.json` 和对应素材，再重跑渲染。
- 只改字幕断句或样式：更新 `subtitles.json` 或渲染配置，再重跑渲染。
- 修改 Storyboard 场景：复用已确认脚本，按影响范围校准素材、字幕和渲染。
- 修改口播文本：更新 `script.json`，重跑 Storyboard、配音、字幕和渲染。
- 修改内容结论：从 `analysis.json` 或更早阶段重新执行。

任何阶段都不得因方便而默认清空整个任务目录。

## 12. 错误处理与可观测性

- 输入提取失败：保留来源元数据并报告失败页码、区块或文件，不进入脚本阶段。
- 分析存在事实冲突：写入警告并要求确认，不把不确定结论伪装为事实。
- Storyboard 校验失败：返回明确字段路径和错误原因，不启动素材或渲染阶段。
- 素材缺失或授权不明：标记缺失项，禁止静默使用未知来源素材。
- 配音、字幕或时长不一致：停止渲染并要求重新校准时间轴。
- Remotion 或 FFmpeg 失败：保留日志和全部已完成产物，使任务可从渲染阶段重试。

未来每个阶段都应记录开始时间、结束时间、输入产物版本、输出产物版本、状态和错误摘要。

## 13. 安全与配置

- 仓库不包含任何真实 API Key、令牌、账号密码或私钥。
- 本地配置通过未提交的 `.env` 等文件注入；未来可以提供不含真实值的 `.env.example`。
- 日志和 JSON 产物不得回写密钥。
- `output/`、依赖目录、构建产物和临时缓存必须由 `.gitignore` 排除。

## 14. 验收标准

第一阶段完成时必须满足：

1. Git 仓库默认分支为 `main`，`origin` 指向指定 GitHub 仓库。
2. 所有约定目录在 Git 中可追踪，生成产物目录保留占位但忽略实际文件。
3. `AGENTS.md` 完整记录内容、视觉、技术、产物和阶段边界。
4. `README.md` 用中文说明项目目的、工作流、目录和未来使用方式。
5. `.gitignore` 排除环境变量、凭证、`output` 生成文件、`node_modules` 和临时缓存。
6. 本文档完整描述输入到 1080×1920 MP4 的生产链、三分钟结构和局部重跑策略。
7. 仓库中不存在真实 API Key。

## 16. 第三阶段 3.1：真实配音驱动时间轴

Knowledge Demo 的口播由 TTS adapter 生成。第一版 adapter 使用 `edge-tts`，不需要 API Key；渲染层只依赖统一的音频、边界和时长结果，不依赖具体供应商。

处理顺序固定为：

```text
Storyboard voiceText
        ↓
按场景生成真实中文配音与 WordBoundary
        ↓
FFmpeg 合并 voice.mp3
        ↓
读取最终实际音频时长
        ↓
解析场景 start/end 与 speechStart/speechEnd
        ↓
生成真实时间字幕
        ↓
Remotion 动态总帧数与音频轨
        ↓
H.264 + AAC MP4
```

字幕优先使用 Edge 词边界。边界缺失、时间不单调或文本覆盖率不足时，按真实场景音频时长做确定性字符权重分配，并在字幕中记录 `alignmentSource`。所有字幕必须落在所属口播和视频总时长内。

生成后的 `storyboard.json` 使用 V1.2，`format.durationMs` 与 `audio.durationMs` 必须一致；最终帧数向上取整，避免截断最后一个音节。`voice.json` 记录供应商、声音、语速、文本指纹、分幕时长、词边界、文件大小和非静音检查结果。

3.1 不包含 AI 内容生成、PDF、OCR、外部素材搜索或自动发布。

## 17. 第三阶段 3.1.1：中文口播自然化

Storyboard 的屏幕文案与口播内容必须分离：`onScreenText` 负责手机端快速阅读和视觉冲击，`voiceText` 负责自然中文口语，渲染组件不得直接朗读屏幕标题或卡片文案。固定 Demo 的口语表达由人工确认；确定性的 narration normalization 只处理列表符号、书面连接词、标点和安全断句，不创造事实，并校验数字与货币单位不丢失。

配音不再按每个场景独立生成，而由 `narration.blocks` 把相邻场景组成连续语义段。Edge TTS 返回的首尾边界用于裁掉冗余静音，同时保留安全余量；语义段内部保持原始连续韵律，段间按照以下策略插入可重复的差异化停顿：

- 普通短句衔接：180ms。
- 普通句尾：320ms。
- 知识点切换：500ms。
- 重要结论：620ms。

Edge TTS 参数由 `VoiceProvider` adapter 和 preset 管理。默认 `natural` 使用 `zh-CN-XiaoxiaoNeural`、`+7%` 语速、`+0Hz` 音调和 `+0%` 音量；另提供 `energetic` 与 `calm` 供 `npm run voice:compare` 人工试听。最终人声可通过 FFmpeg 执行轻量高通、压缩与响度标准化，处理过程不得改变音频时间长度，也不能用于掩盖不自然的 TTS 文案或停顿。

每个语义段的 WordBoundary 会重新映射回所属场景。字幕和场景时间继续由处理后的真实 `voice.mp3` 驱动，禁止恢复固定时间模拟。`voice.json` 需要记录 preset、原始/裁剪时长、裁剪量、停顿类型、边界间隔统计和后处理配置，便于复现与人工验收。

3.1.1 仍不包含 PDF、OCR、LLM 内容生成、付费 TTS、素材搜索或自动发布。
